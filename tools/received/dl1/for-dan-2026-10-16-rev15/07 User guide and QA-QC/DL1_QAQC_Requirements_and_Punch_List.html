1. Purpose and scope

This document sets out what has to be true of DL-1 before a REV is released, how each requirement is verified, and where the evidence stands today. It covers the tool itself: data import, scope, the scheduling engine, execution reporting, the read-only integrations, the dashboard payload, saved jobs, the user interface, security, compatibility and configuration control. Data quality in the source systems (Maximo job plans, the Branch Map, the document register) is listed separately because the tool can only flag it.

The status column is measured, not assumed. Verified means an automated check passed on real inputs and the evidence is named. Partial means it was verified in an earlier REV, or only part of it is tested, and it is not in the current repeatable suite. Not verified means no test exists. Open means it depends on someone outside the tool.

The test pages, runner and golden inputs (SHA-256 manifest) live in Schedule Builder\Tests\, and Run-AllTests.ps1 runs everything from the project folder and writes a dated result to Tests\results\ (QA-01 to QA-04 closed). 2. Quality rules that apply to every REV

These come from the project's own record (CLAUDE.md, Dan Plant's REV 3 handover and the handoff contract). They are the acceptance rules a reviewer applies to any change.

  1. Verify against real inputs. Use the real Maximo feed and workbooks, not synthetic fixtures. A fixture is acceptable only where the real file does not exist yet (the SSCE approvals file), and the status says so.
  2. The regression baseline must reproduce exactly after any change: WO.csv of 2026-09-25, West Vela BOP1, commence 2026-10-05, crews blank gives 143 tasks, 148 items, 917.5 h, finish 2026-10-15 07:30, 31 critical, 95% coverage. A read-only REV must also leave planningData byte-identical.
  3. The dashboard payload is additive-only. No field is renamed, removed or retyped.
  4. Key everything on the task id (wo:<WONUM>), never on the job plan code, which is not unique per task.
  5. Never edit a shipped REV. Each release gets its own REV folder and badge. Earlier REVs are the rollback.
  6. Read-only towards every other system. DL-1 reads Maximo, SACRED, the CoC Tracker, the WCE Hub, Synergi and eDOCS, and writes to none of them. REV 13's posting to SACRED is the single exception, and it is gated.
  7. Nothing fails silently. A missing input, a stale file, a low coverage figure or a mismatch is shown on screen, never dropped quietly.
  8. No credentials in the tool or its files. Sign-in is always done by the user.
