## Read this first — three rules

**1. One report at a time. Post it. Clear the workspace. Start the next.**
Do **not** build all four in one workspace. SSORT names the posted file after the *first* report type
it finds, so a CBM inspection and a pre-deployment checklist built together post as **one** file
called `…_cbm-inspection.json` with both inside — and the checklist never appears as its own row on
the dashboard. SSORT asks you first (*This workspace holds … It posts as ONE report*): press **Cancel**. Use **⊘ New Trip**
between reports.

**2. Use your allocated date, and put it in the right box.**
It is a different box in each tool:

| Report | Tool | The box that names the file |
|---|---|---|
| Daily report | WCGRRT | **Report Date**, in the Daily Report block — *not* the visit date |
| Surface test | SSORT | **Log Date** in Vessel Information |
| CBM inspection | SSORT | **Log Date** in Vessel Information |
| Pre-deployment checklist | SSORT | **Log Date** in Vessel Information |

Ten of us posting the same report type on the same date would produce the same file name, and on the
dashboard a same-name post replaces the earlier one. Your own date is what keeps your work yours.

**3. WCGRRT will ask you if you really mean your date. You do.**
Because your date is a couple of weeks back, Post will show you this:

> This report is dated 2026-10-0n. That is nn days ago. The date sets the posted filename, so posting
> it will replace any report already filed for 2026-10-0n. Post it as 2026-10-0n?

Click **OK** — today. On the rig, that dialog almost always means you have the wrong date, so read it
rather than clicking through it. Getting it wrong is what lost a day of West Capella's work.

> real attachment on the email NOV receives. Read the confirm — it tells you which.
