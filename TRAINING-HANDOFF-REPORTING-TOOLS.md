## Three things only you can answer for the script

1. **What a trainee sees when Post fails** on each tool, word for word, and what they do next. The
   class must leave knowing the difference between "saved", "posted" and "on the dashboard".
2. **The current guards list**: every check the tools now make before Post (size, rig identity,
   attestation, dates, photographs), one line each, so the workbook's "why did it stop me" table is
   complete and true for the REV the class will use.
3. **Which REV the class trains on.** Name it, and freeze it for the class week: a revision shipped
   between draft and delivery changes the screenshots.

## What we need from you, and in what form

The dashboard session builds the pack (slides on the Seadrill template, the trainee workbook, the
trainer's script, the sandbox scanner configuration). You supply the substance for your modules, in
this form, so it drops straight in:

1. **A walkthrough script per module**, markdown: what the trainer clicks, in order, what to say at
   each step in one or two sentences, and the three mistakes to demonstrate on purpose with what the
   tool does about each. Twenty to thirty steps per module is right.
2. **Screenshots** for each step that needs one: PNG, light mode, 1600 px wide, the asset set to
   **SSCE Equipment** (never a real rig), no real names. Numbered to match the script.
3. **Three questions per module** for the workbook, with the answers, the kind a Technical Section
   Leader should get right after the session.
4. **Sample files for the exercise**: one saved (not posted) report of each type your tool makes,
   on SSCE Equipment, so the trainer has a known-good answer to compare against.
5. **One slide's worth of content per module**: the five to eight points that must be on the
   screen while the trainer talks. We lay it out; you write it.

Standing rules, unchanged: **nothing is posted from training**, trainees save locally and the trainer
drops the files into the training folder that a second scanner configuration reads; **SSCE Equipment**
is the only asset used; nothing in the transport or the tool changes for the class.

**When:** draft 1 to Dan [two weeks before the class date, which Dan sets]; one review round; final a
week before. Send it the way every handoff travels, a markdown file plus the PNGs in a folder.

Not needed from you: anything about the dashboards, the flows, the scanner or the sandbox; those are
ours. Precharge, AAB and the COC tracker have their own handoffs.
